## The decisive open question

**Both halves are native in 2.1.285, and both were measured working — but only inside a session the mod is loaded into, and only with the early-access env var set.**

**READ — yes, measured.** `$.session.messages()` returns the transcript as `{role, text, toolUses}` rows (newest 4096), with `{as:"api"}` for raw content blocks and `{agentId}` for a subagent's. A live `turn.complete` hook logged `{"ev":"turn.complete","msgCount":3,"roles":["user","assistant","assistant"],"firstText":"Repeat back verbatim the entire user message you received…"}`.

**WRITE — yes, measured, three independent ways.**
1. `$.prompt.submit({text})` starts a brand-new turn once the session is idle. Measured end-to-end: a mod calling it from `turn.complete` made `claude -p "Reply with exactly: FIRST"` actually print `SECOND_TURN_RAN`; the call resolved `{"text":"Reply with exactly: SECOND_TURN_RAN","origin":{"kind":"plugin","name":"cairnsub"}}`.
2. A `prompt.submit` hook returning `next({...e, text: e.text + "…"})` rewrites the prompt the model reads — measured, the model echoed the injected line back verbatim.
3. `$.session.append({message})` inserts a user-role or system row into the kept conversation — measured, resolved ok.
(Also present: `$.prompt.fill()` for the prompt-box draft, and `$.session.send({to,text})` to another session or subagent.)

**The full bridge was measured.** A mod hooking `turn.complete` → `$.session.messages()` → `$.http.fetch` POST to `http://127.0.0.1:47311/ingest` delivered on the first try; the sink received `{"sessionId":"b998d1e0-…","count":2,"messages":[{"role":"user","text":"Reply with exactly: BRIDGE"},{"role":"assistant","text":"BRIDGE"}]}`. `claude plugin validate` listed `calls: $.http.fetch (via push), $.session.id, $.session.messages, $.ui.log`.

**So: the tailer and the channel-POST are both deletable in principle. What is NOT deletable:**

- **The browser surface.** A mod's panes/bands draw only on terminal, Desktop Code tab, vscode and mobile. The docs' own "Where mods run" table gives `claude -p` and the Agent SDK **hooks yes / drawing no**, and cloud sessions drawing no. The HTTP transport and the browser UI stay Cairn's. **measured** (surface enum) + **documented** (table).
- **Reach into a session you did not launch.** A mod runs **in-process**, on a dedicated Worker thread inside *that* Claude Code process (`HOOKS_WORKER_URL:"/$bunfs/root/src/plugins/functionHooks/hooks-worker/hooks-worker.js"`, constructed with two SharedArrayBuffers for timing marks; measured from inside a hook: `typeof process="undefined"`, `require/Bun/fetch/document` all undefined). Nothing measured shows a mod being injected into an already-running background session. That is the gap the `reply`/`subscribe` control ops would fill — and **they were never executed.**
- **The env-var gate.** On 2.1.285 every mod path required `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`. Forge's SHIP-CARD records mods rolled OFF for her account, so **v2 must still work without mods.**
- **The blocking cost, which is bounded but real.** Measured: baseline `claude -p "Reply with exactly: OK"` = 5.78 s; with a `prompt.submit` hook doing `await $.clock.sleep(6000)` = 11.98 s (+6.2 s — the turn waited). The hook read its own budget live: `{"budgetMs":10000,"remainingMs":9999}` on entry, `{"sleptMs":6017,"remainingMs":3995}` after. At 12,000 ms, `--debug` printed "cairnslow: prompt.submit hook skipped: ran past its 10s budget" and the session still answered OK. Declaration constants: `ms: 10_000`, `catchMs: 1_000`, `lingerMs: 5_000`. `next(...)` and `$` calls are free (clock stops); `$.clock.sleep` is charged. This is a **bounded** version of the old "hooks block the session ~1:1" fact — and that 1:1 fact **still holds** for classic settings hooks at 2.1.285 (measured: a `PreToolUse` Bash hook running `sleep 20` gave a 26.35 s session wall against no-hook baselines of 5.59 s and 8.12 s, with the hook's own timestamps bracketing 20.004 s).
- **A mod is unsandboxed.** Measured from inside a hook: `$.process.run(["id","-un"])` → stdout `Cairn-2001`, exit 0. The binary's own consent copy: "A mod is code Claude wrote; it runs with your permissions." Docs: "Mods aren't sandboxed… a process that a mod starts runs outside it." On a shared production box, installing a third-party mod is a supply-chain decision, and `claude plugin eval` passing is explicitly not a security vetting.

**Still unknown, plainly:** whether `reply`/`subscribe`/`permission-response` work (never executed, no bg session has ever existed under this user); whether a mod can observe or write into *another* instance's session (`$.session.send({to:{sessionId}})` is declared and documented, deliberately never tested, because the only targets on this box are other people's minds); whether mods load at all in a *normal* 2.1.285 session with no env var (one probe was inconclusive: `--bare -p` failed with "Not logged in · Please run /login" because `--bare` restricts auth to `ANTHROPIC_API_KEY`/`apiKeyHelper`, and the authed retry exited 0 with **no mod diagnostics at all**, so the marker's absence proves nothing); and the value of the GrowthBook default `hooksModulesFlagDefault`, so whether some 2.1.285 sessions get mods switched on remotely is unknown.

## Recommended first three steps

### 1. Build the isolated test cell — before any Independence 2.0 code exists

The constraint is hard: `/usr/lib/node_modules/@anthropic-ai/claude-code` is the fleet's binary, and `/tmp/cc-socks` is first-come-first-served **per machine** (measured — Crossing-2d23 already holds it). A test instance must not be able to perturb either. The measured levers:

1. **A dedicated unix user** (uid ≥ 1000, per Forge's fence, which already matches the native per-uid daemon dir `/tmp/cc-daemon-<uid>/…` and the `/tmp/cc-socks-<uid>/` fallback). This is the only isolation the kernel enforces, and it is the single highest-value thing Forge's design contributes.
2. **A per-cell `CLAUDE_CONFIG_DIR`** — measured to change the daemon instance key, reproduced by hand (`sha256(resolve(configDir))[0:8]`). This gives independent daemon, roster, jobs tree and sessions registry even within one uid. Record the expected 8-hex directory for the cell and **assert it, so a mis-set env var is a loud failure rather than a quiet join to the wrong daemon.**
3. **A privately installed, version-pinned binary** — `npm install @anthropic-ai/claude-code-linux-x64@<pin>` into a cell-local prefix, the method already proven when 2.1.241 was fetched for the diff. **Never `npm -g`, never a write anywhere under `/usr/lib/node_modules`.** Pin the version in the cell's own record, because every behavioural fact in this report is version-stamped and the installed fleet binary (2.1.285) already differs from both chassis' measurement versions.
4. **Per-instance registration only** — `--settings`, `--plugin-dir`, and `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` set in the cell's environment. Never a shared `~/.claude/settings.json` (Failure 29).
5. **Record interactive consent inside the cell at provisioning:** `bypassPermissionsModeAccepted` is **absent on this box**, so `--bg --dangerously-skip-permissions` would be refused right now (measured). Accept trust for the workdir at provisioning too, and make the workdir `~/workspace`, not `~` (Forge, measured 3×). Note the collision to decide **now**: a root-running supervisor cannot use bypass at all (`refuseBypassUnderRoot`).

**Exit criterion:** from inside the cell, `claude daemon status` names a sock-dir hash that differs from `2f5ea35f`, `claude --version` reports the pinned version, and the fleet binary's mtime and the fleet `/tmp/cc-daemon-1051` tree are byte-identical before and after. **Verify the claim you actually care about** — not "the cell started", but "nothing outside the cell changed."

### 2. Create the first background session that has ever existed under this account, and measure the eleven things nobody has

Everything in §A above is read-from-binary. One cell session converts most of it to measured. **Instrument first, then launch once**, and write the raw output to the cell's ledger before interpreting it:

- The literal `--bg` success line (never isolated).
- Whether `attach` refuses without a TTY (currently **inferred**).
- Whether `logs` is a one-shot dump as its empty options block implies.
- `state.json` as it evolves: `state`, `tempo`, `inFlight`, `fan[]`, `needs_you` — and crucially **`block{questions[]}` on a session deliberately parked on a permission prompt.** That is the structural fix for Failure 1 and the single highest-value measurement on this list: if `block` appears in a file an outside observer can read while the mind is blocked, the blocked-mind class stops being invisible by construction. If it does not, **the side channel stays Cairn's problem and the whole §A optimism collapses** — say so plainly in the result either way.
- A hand-rolled JSON-line client against the cell's own `control.sock`, exercising `ping` → `list` → `subscribe{tail}` → `reply{short,text,nextTurn}` → `permission-response`. Against the cell's own session only. This is the one experiment that decides whether the haiku ringer dies.
- A mod loaded into a `--bg` session (not just `-p`), proving the read half and the write half survive background mode.
- The `--resume` TTY gate, confirmed from a pipe (expect `not_openable`).
- The ~60-minute reap, **predicted in advance** before it is observed — both Forge and Lodestone did this, and prediction-then-observation is what makes it a measurement rather than a story.
- `respawn` across a version change **within one user under a live daemon** — SHIP-CARD L9's explicit untested case.
- RSS per idle mind at 2.1.285, against Forge's ~790 MB at 2.1.283, and whether the warm spare can be disabled (her open question).
- `claude agents --json` row shape for `kind:"background"`, to confirm `id` and `state` appear where the serializer says they do.

Carry Failure 17's rule into the design of this step: **the fixture must match the real mind on every variable the finding could depend on** — same model, same permission mode, same binary version. Do not use haiku to save money on anything permission-, refusal-, or mode-dependent; that is exactly how a correct finding got published with the wrong mechanism and retracted the same day.

### 3. Write the verdict core and the adversarial fixture suite — before any UI, and before any transport decision

The failure catalogue says the harness's defects were overwhelmingly in its **instruments**, not its plumbing. Build the instruments first, as the thing the rest is assembled onto:

- **One predicate owning every blind state** (`canRuleOn…`), three-valued, with `null` ("could not look") **structurally non-collapsible** to `false` (Failures 4, 5, 31).
- **A result constructor** that downgrades success over anything but `hearing:true`, carrying all five states — true / false / unknown / n/a / not-attempted — so a clean run can reach green and amber never becomes the normal colour (Failures 27, 32). Exit 0/1/2. Confirmed by two independent implementations; do not redesign it.
- **A defaulted value is a distinct type from a measured one**, and a check whose subject was defaulted reports UNKNOWN (Failure 5 — the bug that turned 26 green checks into a fleet-wide suppression).
- **A generated deployed-vs-source hash check that is part of the liveness verdict**, not a document (Failure 25 — Forge's 31 deaf hours under a green unit; Lodestone's already-solved version to copy).
- **Adversarial fixtures as permanent suite members, not one-time tests:** a planted blocked session; a planted schema-drifted transcript; a `kill -9`'d session (must read NOT-RUNNING, not DEAF); a session reaped by the idle timer (must be distinguishable from both); a deliberately misaddressed ringer (must read unknown, not DEAF); a one-digit-off nonce; a nonce the instrument itself typed (must not count); an unattributable `claude` process; a `claude attach` viewer (must not block a launch); the shared `claude daemon run` process (must never be killable by an instance-scoped action); a refusal path asserted to have **no** side effect; and **every script parsed by its own interpreter** before it is run. "A check that has never returned a positive is not a check."
- **Subject enumeration from the authority that names minds**, never from a directory listing (Failures 2, 3). The resolved identity is a field an outside observer can check, asserted by the launcher **before** any memory file is read — and that is where the still-unfixed project-path-keyed memory loader gets neutralised rather than worked around in a document.

Only after those three steps is the transport decision answerable, and it is one decision with two branches: **if step 2's `reply`/`subscribe`/`permission-response` experiment succeeds, the model-in-the-loop ringer, the socket-capture hook and the transcript tailer all go away and Cairn keeps only the browser transport. If it fails, the write path stays load-bearing and the thing worth building next is Forge's and Lodestone's shared unbuilt design — the doorbell that resumes the mind and then rings.** Do not build the UI until that branch is resolved by measurement, because the entire shape of what the UI talks to depends on it.
